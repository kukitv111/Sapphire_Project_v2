# ADR 0002: prepaid tariff purchases and session settlement

Status: accepted for internal wallet payments; external payment provider integration remains a TODO.

A purchase is identified by `(user ID, Idempotency-Key)` and stores a tariff snapshot, the wallet payment ledger ID, purchased cents and available prepaid cents. The unique database index enforces the idempotency key. The same key for another tariff is a conflict. The wallet is debited once at purchase, atomically with the entitlement and payment ledger entry. A failed write or insufficient wallet funds creates neither purchase nor debit. Simultaneous writes use optimistic concurrency plus a serializable Billing transaction; the losing request receives a conflict and can retry with its original key. No card processor is involved. `TopUpWallet`'s external payment provider is still a separate TODO and must not be represented as settled card payment without a provider confirmation.

Metered tariffs sell one hour of prepaid credit: minute tariff price × 60, or hour tariff price. Package tariffs require an explicit package price and sell the configured duration plus bonus minutes. Rates and price are copied into the entitlement at purchase, so later tariff edits do not change the customer's purchase. A session supplies the entitlement ID and requested duration (maximum three hours). The server chooses its start time. Billing reserves the planned price from available prepaid credit before Session commits an active session. Two concurrent starts cannot reserve the same cents. A normal completion charges by elapsed time, rounded up to started minutes/hours or the package fraction, capped at the reserved amount and planned end. Any unused reservation returns to the entitlement. Cancellation returns the entire reservation. Duplicate completion/cancellation events are ignored by the Billing inbox and reservation status.

The wallet balance is already reduced at purchase; a later session settlement consumes the prepaid entitlement balance rather than debiting the wallet a second time. Remaining entitlement credit is retained for another session. There is currently no cash refund of unused purchased credit, expiry, transfer, cross-entitlement split payment or overrun charge. Those require explicit commercial rules and ledger entries. Session time past its planned end is capped at the reservation, so the user cannot acquire unbilled extra time through this model; workstation access enforcement must terminate service at the planned end. The UI should display purchased, available and reserved prepaid balances separately from the wallet.

The cancellation endpoint is intended for sessions that never started or for operator-approved fault cancellation. It returns the entire reservation and should be policy-restricted in a live installation to prevent free gaming; ordinary early departure uses completion and only returns the unused portion. Settlement is eventual after Session commits its completion event. Operational monitoring must alert on old active reservations and dead-letter events. Automatically releasing a reservation merely because its planned end passed would create a free-session risk if the completion event is delayed, so this version requires explicit reconciliation.
